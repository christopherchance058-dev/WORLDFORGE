Read [AGENTS.md](AGENTS.md) for development rules. This file records current architecture and compatibility, not a work log or proof of current test results. Read affected source before changing it. ## Product and preferences

Local-first worldbuilding encyclopedia with independent worlds, connected lore, category folders, nested locations, maps and a visual history timeline. No account/cloud service required. History has Events/Eras tabs; Maps and Timeline are separate Atlas destinations. World banner/controls appear only on All entries. Creative vocabulary and calendars remain open; relationships never imply simulation rules.

The user is nontechnical; handle implementation and explain outcomes plainly. Discuss design unless execution is requested. README edits require an explicit request; its concise feature descriptions and unchanged backup/restore/moving/update instructions are for users. Do not append developer notes there. Commit/push authorization applies to the current work only.

**Testing:** focused checks by default. Full-suite runs belong only at completed development milestones, always after explicit approval, including repeat runs. Prompts/fixes/commits/pushes are not milestones by themselves. Do not batch the entire suite to bypass approval. Documentation cleanup needs only content/link/diff checks.

## Runtime and source map

Plain HTML/CSS/browser JS with shared globals; Node **24+**, CommonJS, built-in `node:sqlite`. No frontend framework/build. Runtime dependencies: `sharp` (images), `archiver` (ZIP export), `yauzl` (ZIP import); Playwright for tests.

- `npm ci`: install locked dependencies when needed, not every task.
- `npm start`: Node server, default `http://localhost:3000`, bound to `127.0.0.1`; `PORT` overrides it. Do not open index.html directly.
- Targeted example: `npx playwright test tests/connections.spec.js`.
- `npm test` / unfiltered `playwright test`: full suite; approval required.
- `tests/fixtures.js` starts isolated temporary libraries/servers and handles restart/cleanup. `/usr/bin/chromium` is used when present; otherwise install Playwright Chromium only if missing.
- Existing `.github/workflows/node.js.yml` runs tests on main pushes/PRs; this documentation consolidation does not change that workflow. Configuration is not proof of passing hosted CI.

## Storage and recovery contracts

- **SQLite schema 5; API/ZIP format 6**, independent versions. Optional specialist fields are JSON, not separate lore tables. Preserve unknown and legacy fields.
- Library root: `WORLDFORGE_DATA_DIR` or `data/` beside server.js. It contains `worldforge.sqlite`, possible WAL/SHM, `images/`, `backups/`, `staging/`; additional worlds use `worlds/<UUID>/`. Never test against it. Copy the whole root with the server stopped or use portable ZIPs.
- Saves carry the full metadata revision. Requests select `X-Worldforge-World` (default `default`); image/download URLs use world-aware lookup/query parameters. Missing fields from compatible older PUT clients preserve existing additive metadata.
- Additive tables include `world_catalog`, `world_appearance`, `world_trash`, `category_colors`, `historical_eras`, `history_settings`, `folder_organization`. These additions do not rewrite existing entries at startup. Schema 3/4 upgrades snapshot before transactional conversion; first world-catalogue initialization integrity-checks a before-worlds SQLite snapshot.
- World deletion verifies a complete ZIP, checks metadata/profile revisions and hides the world without deleting its files. Trash supports restore/download; deleting the last world creates an empty replacement. Trashed APIs return 410; legacy unscoped requests never silently redirect. Older apps may ignore Trash.
- Immutable images use generated file IDs, SQLite checksums and `/api/images/<id>`, not localStorage/base64 payloads. Limit: 50 MB / 80 million pixels. Entry images accept PNG/JPEG/WebP/GIF; map UI accepts PNG/JPEG/WebP. Duplicate bytes may be reused. Removed/cancelled images remain registered/exportable; no cleanup exists. Cross-world lookup preserves stable references.
- A ZIP exports the selected world only: manifest, metadata and all its registered images. Restore keeps the destination world's name/description; validates paths, records, checksums/images/references; creates rollback and replaces transactionally. Accept ZIP 3–6 and legacy JSON arrays/versions 1–2 (v1 preserves current maps). Old replacement imports without eras/folders explicitly clear those features. Browser `worldforge.entries.v1` migration is idempotent and preserves originals/checkpoints.
- Use current-version backups for expanded metadata; older releases may omit folders/eras/colors or reject newer optional fields. Restore/migration experiments require isolated recovery verification.

## Shared UI and linking

`EntryCards` uses title/tags beside a square thumbnail and a full-width preview below; no metadata rows. Small/Medium/Large preference is `worldforge.entry-card-size` (legacy Character preference supported; Compact maps to Small). Preview prefers Summary then Description, with 18/40/70-word budgets, intact reference badges and up to three tags plus a remaining count. Native title/preview buttons are siblings, never nested. `EntryProfile` supplies shared reading headers, aligned neutral label/value rows, headings/actions and hidden empty fields. Square previews never alter originals; full-image links remain available. Entry/gallery guidance is 1024 × 1024; banners 2400 × 800; maps retain natural proportions.

Categories permit initial name/icon then color-only editing (32 presets/custom/reset); colors use shared deterministic defaults and theme-readable shades. `CategoryColors.apply` decorates only clickable references. Category browsers share search/card size/New/sort/count; Characters retain specialist filters and Locations retain hierarchy.

Shared Description/Summary and appropriate specialist narratives use `DescriptionLinks.bind`/`collectFields`, `renderField`/`plainField`. Registry v1: optional `descriptionReferences`, `summaryReferences`, or owner-local `textReferences[field]`, with `{version:1,items:[{token,entryId,label,kind?}]}`. Only registered exact tokens become links; token-like text stays literal. Stable IDs/escaped labels/UUID markers preserve live names and unavailable fallbacks. Era refs use `kind:"era"`/`era:`; ecosystem refs use `kind:"ecosystem"`/`ecosystem:`. Missing kind means entry; IDs may collide across all three record types. `DescriptionLinks.targets` caches against both era and ecosystem arrays, projects Canvas names/art/descriptions with the canvas badge, and resolves rename/deletion by typed stable ID. Shared @ pickers, reading links and nested previews include ecosystems; navigation opens the standalone Canvas with the normal dirty-canvas guard. Ecosystem preview prose is capped at 70 words with intact registered badges.

Compact contenteditable chips synchronize backing textareas, accept text-only paste, preserve surrounding text and never truncate writing; per-field undo holds 100 snapshots. Registries stay with their row/gallery/travel owner, not numeric array paths. New owners must join nested server validation. Existing coverage includes Character linkFields (36), Faction aliases/motto/multiline lore (15), Geography government/environment/dangers/resources/secrets and travel method/notes, Creature's six and Magic's five narrative fields, connection notes/history, gallery captions and era Description. Classifications/dates/IDs/neutral picker notes and standalone-pin descriptions intentionally stay plain. Managed-image/category-icon autocomplete and safe previews share the same implementation.

`text-limits.js` defines visible-character budgets: Summary/Short description 240; Description 6000. Unicode code points, spaces, punctuation and line breaks count; a registered badge counts as `@` plus its live target name (saved label when missing), never its encoded ID/UUID or unavailable-status decoration. Escaped/unregistered token text remains literal. Rich editors show live counters and retain over-limit drafts until corrected; plain Map/pin/world descriptions use the same counters and validation. Existing unrelated specialist narratives, titles, dates, notes/history and classifications retain their own contracts. Canvas visible annotation text has its own 2000-character budget.

Ordinary `Store.replace` validates changed description fields recursively by stable owner ID against the current stored state before any write; new/changed over-limit prose rejects atomically. Previously over-limit text can remain unchanged (including routine outer whitespace normalization and unused reference cleanup), so unrelated edits/renames/deletions remain possible. Linked map-pin snapshots mirror their explicit source without a second budget; unlink/deletion snapshots preserve the old source prose. `validateState`/owner models still perform structural, reference and bounded serialized-capacity checks (1,000,000 code units for description backing strings); visible budgets are enforced at the revision-aware save boundary. These are separate limits, not an allowance of one million visible characters. Restore/import uses an internal `preserveDescriptions` option, never a client flag, after archive validation and existing rollback safeguards. No schema/archive-version/startup rewrite occurs; the original library and verified backups remain recoverable. New annotations/long serialized badges require this build or newer to edit/restore in full.

`Navigation` is session-only, not browser History API: Q/E and controls restore reading/workspace/filter/scroll state, skip deleted targets and respect dirty/upload/save guards. Refresh/world change/restore resets history. `editor-keys.js`: Enter advances visible text controls then focuses Save, Shift+Enter adds a newline, autocomplete has priority. Errors appear under headings in `.form-error`, scroll into view and retain drafts. Era dialogs have independent guards; map restoration does not reenter browser fullscreen.

## Connections and folders — completed shared features

Common questions live in `ConnectionModel.standardGroupsFor`: Characters People & relationships; Factions Support & associations; Locations Origins & associations; Magic Practitioners & teaching / Origins & associations; Creatures Habitat & interactions / Magic & significance; History Causes & consequences / Other participants & related events; Eras Events & associations. Custom/future categories inherit Associations. Reuse specialist controls rather than duplicate them.

Common fields are present but non-required. Niche suggestions come from `suggestionsFor`; the shared **Connections & linked lore** editor also supports any custom field name, rename/remove, entry targets, typed eras, neutral notes and @ narrative notes/history. Empty default questions are draft-only. Saved matching rows retain IDs/owners/unknown fields; transient routing/default markers are stripped. Character/Creature/Magic keep their `relationships` arrays; generic entries/eras use optional top-level `connections`. Rows support stable IDs, `entryIds` (legacy `entryId` mirrored where needed), `eraIds`, type (120), description (6000 visible characters with the shared policy), history (6000), selectionNotes, textReferences, formerTargets/formerEraTargets/formerEcosystemTargets; limits are 200 rows/owner and 500 unique targets/list, excluding typed self-links.

Legacy Character/Faction relatedIds and Location relatedEntryIds appear as an editable Other connections draft. Only successful explicit save moves IDs/notes to generic connections and clears the old lists. Startup/cancel/failure never migrate saved content. Specialist structural constraints remain unchanged.

`Connections.structured` centralizes specialist facts and flexible rows. Exactly one reading section uses EntryProfile horizontal badges/chips, truthful outgoing/incoming provenance, separate registered @ mentions, category/direction/search filters, 12-row disclosure and expandable notes; Navigation restores filter/disclosure state. Old specialist backlink hooks are compatibility no-ops. Deletion snapshots preserve former names/written lore, never infer reciprocal facts.

Characters/Creatures manually store optional `livedEraIds`/`livedEraNames`; live era art/names or safe missing-art/deleted-era fallbacks appear as banners. No inferred dates/lifespan. The heading is **Eras lived through**. Gallery details carry `data-editor-gallery`; `Connections.update` moves them into final `#entry-gallery-editor`, retaining category owner/draft callbacks. Galleries always follow lore/connections/eras; this hook adds no gallery storage to categories without galleries.

Folders: `organization:{folders:[{id,category,name}],assignments:[{kind,id,folderId}]}` lives separately from lore. One flat per-category folder per entry/era; tags handle overlap. Typed IDs prevent event/era collisions. All/Unfiled/scoped search, counts, menu/native drag moves and creation context share Folders hooks. Creation assigns only after success and reveals the new card; moves preserve lore/IDs/updatedAt. Deleting a folder keeps entries Unfiled. Case-insensitive duplicate/reserved names fail validation. Read/import missing memberships recover to Unfiled; omitted organization on old PUT preserves it, pruning deleted/category-changed records. Navigation resets folder state on world/restore/reload. Locations filter cards, not hierarchy; History shares folders across Events/Eras; Maps/Timeline ignore folders. Future specialist browsers reuse `Folders.bar/matches/origin/withNew`.

Tests: `connections`, `named-fields`, `folders`, `folder-integrations`, plus relevant specialist/linking/navigation/storage suites. Historical common-field milestone: all 232 distinct tests had passing results across a 231/232 broad run and focused rechecks after an obsolete gallery selector was fixed. This is not a current test claim; old per-milestone reports remain in Git history.

## Specialist records and Atlas

- **Characters:** optional `entry.character`; blank title becomes Unnamed character, description may be blank. Open type/status and fantasy dates; `entry.image` is the portrait. `character.gallery` has up to 50 stable-ID immutable images with @ captions. Shared snapshot includes Creature/Magic draft IDs/images; gallery-only edits remain guarded.
- **Creatures:** optional `entry.creature`; every creative field, including name, is optional (Unnamed creature fallback). Classification is plain open text (120); appearance/habitat/nature/lifeCycle/abilities/significance are linked narratives (6000 each). Relationships/gallery share Character conventions. Bestiary projects to Creatures on reads/imports without startup writes; save persists it. If both names/case-insensitive collisions exist, preserve them separately and show a notice. IDs/lore/icon/colors survive.
- **Magic:** optional `entry.magic`; all creative fields optional (Unnamed magic). Plain Type (120), five linked narratives source/effects/limits/risks/context (6000 each), plus shared common/niche/custom connections. Unknown payload fields survive edits.
- **Factions:** optional `entry.faction`, 19 specialist text fields in nine groups, 15 linkable; shared title/description requirements remain. Headquarters/territory must be Locations; highlight members do not rewrite Character affiliations. Structured deletion preserves written lore.
- **Locations:** optional `entry.location` or category Locations; only name required. Open type/status, learned hints and twelve type presets. Parents must resolve to locations; reject cycles/missing parents, max depth 64. Parent deletion reparents direct children, never cascades. Add child supports create or move existing, preserving descendants/content and confirming parent changes. Up to 500 links/list and 100 travel rows; estimates manual, removed destinations retain labels. Ruler/controlling-faction arrays and Character birthplace/home/current-location / Faction headquarters arrays fall back to legacy singular IDs and mirror their first selection on save. `Geography.flexiblePicker` is the shared chip/search/checkbox/unlinked-note control; parent/travel destinations stay singular.
- **Maps:** optional ordered image canvases, each owning pins; coordinates normalized to [0,1] relative to that image. Linked pins resolve current entry content; deleting entries leaves standalone readable snapshots. Uploads, hover/reading panels, pan/zoom, fantasy symbols and fullscreen use existing map workspace.

**Chronology:** optional `entry.history` stores null or `{year,precision:"year"}` startDate/endDate, eventType, dateCertainty, calendar, timeUnit, startLabel/endLabel. Numeric range −999999…999999; blank is unknown, explicit zero valid. Missing start falls back to legacy year; explicit null does not. Chronology edits mirror legacy year; unrelated legacy edits do not insert history. Unknown certainty clears numeric dates/year but retains written labels; switching certainty before save retains draft numbers. No reversed ranges or implied duration. Calendar/unit/certainty/type are open text; default unit Year, no date parsing/conversion. History participants retain specialist category constraints and neutral selection notes.

**Eras:** independent `historical_eras` records `{id,name,description,textReferences?,color?,chronology,updatedAt,image?,timelineImage?}` and `history_settings` chronology `{name,calendar,timeUnit}`. `EraModel.project` provides read-only shared geometry/cards/links. Events/Eras share History browsing; eras also appear on All entries without duplicate entry records. Card image and timeline image are independently validated, remapped and backed up. Deleting events and eras does not delete each other. Old PUT omissions preserve eras/settings; replacement old imports clear/default them.

**Timeline:** one read-only projection per selected world's calendar/unit scale. Exact compatible pairs only; written dates do not imply coordinates and incompatible/undated records stay accessible in paginated lists. World chronology chooses the initial scale, never rewrites dates. Geometry uses x=(year−center)×pixelsPerYear+width/2, 1/2/5 ticks, overlap packing, horizontal culling and virtualized event/era rows. Limits: whole-unit coordinates, max 160 px/unit, ±999999 extent. Missing era ends are boundaries, not durations. Illustrated/Compact/Hidden eras share geometry; overlaps are valid. Search/type/certainty filters combine (type only affects events); Fit uses matching events/shown eras. Help/Jump/New disclosures and pan/zoom controls sit above the ruler. `HistoryTimeline.reveal(id,kind)` selects scale, clears filters and focuses numeric/virtualized rows or expands undated lists. Views/pan/zoom/filters are session state, not library records.

## Canvas Atlas and reusable diagrams

`canvases.js` owns a standalone Canvas destination beside Maps and Timeline. There are no Ecosystem pages, membership pickers or Overview/Entries/Canvas tabs. Canvas and Maps share `EntryCards.libraryTools` for search, preview sizing, create, title/recent sorting and counts. Their dedicated `atlasCard`/`atlasGrid` helpers use image-above-title tiles instead of encyclopedia entry cards; no folder actions are attached. Canvas offers Compact tiles and full-width Banner rows with vertical spacing, remembered in `worldforge.canvas-library-layout`. Compact prefers thumbnail then banner; Banner prefers banner then thumbnail. Maps retain image-first tiles and their natural-image editor/normalized pins. Preview cropping never modifies originals. `worldforge.atlas-preview-size` controls Atlas tile widths/banner heights independently of encyclopedia card sizing. The actual entry list beneath a diagram keeps ordinary EntryCards.

A canvas detail page presents its name/actions, optional banner/description, editable diagram, a searchable/category-filtered list derived only from its entry nodes, with no Connections & linked lore reading section on this page. Existing association metadata remains editable/preserved and encyclopedia entries still link to canvases. The pencil edits metadata in a guarded dialog; Apply details stages changes. One green Save canvas and its live status sit in a compact sticky title header; the same controls move to the right-hand diagram toolbar in fullscreen and return on exit. No bottom save bar is rendered. Metadata and diagram commit together. New canvas creation saves an empty standalone record first. Thumbnail (1024 × 1024 guidance) and banner (2400 × 800 guidance) are independent optional uploads. Missing banners produce no placeholder on the detail page. Names/tags are plain identifiers; descriptions, shared connection prose and diagram notes use the universal @ codec. Add entry accepts any existing encyclopedia category directly. Removing a card removes only that diagram's connections/card, never its entry or another canvas's diagram.

Compatibility is deliberately lossless: the existing `ecosystems` JSON collection/table, `ecosystem:` reference kind, `ecosystemIds`/`formerEcosystemTargets` connection keys and `ecosystem-model.js` filename remain an internal persistence boundary. Display names, badges, search suggestions and navigation all say Canvas and use its icon. IDs/tokens are not rewritten. The old `ecosystems.js` UI module is replaced by `canvases.js`; browser/global integration uses `Canvases`. Navigation stores the Canvas workspace under session `atlas` state. No SQLite schema/API/ZIP version changes or startup record rewrites are required. Older releases may reject unrestricted records without old member arrays; use this release or later to open/restore saved standalone canvases.

`EcosystemModel.detach` makes a cloned standalone draft: existing diagrams/positions/labels/notes and unknown fields stay intact; old selections without diagram nodes become ordinary Related entries rows, and linked places become Related places rows. `standaloneCanvas:true` makes conversion idempotent. Legacy arrays/names are retained as compatibility metadata, never used to constrain adding cards or derive the current entry list. Conversion reaches disk only on explicit Save. Existing @ links and structured backlinks resolve the same IDs as canvases. Real diagram appearances and explicit associations remain distinct; no reciprocal lore is inferred.

`ecosystem-model.js` validates general canvas records (up to 1000): name, description, optional tags/thumbnail, banner, shared connections, linked prose and diagram. Old association arrays are optional and retain ID limits. `storage.imageRecords` includes both artwork slots for validation, checksums, backup/Trash/checkpoint exports and cross-world import remapping. Existing portable backups are accepted, imports without this collection clear it as before, and all original images remain registered. Failed saves preserve drafts. Isolated recovery checks compare remapped artwork bytes and record content, not world-specific image IDs. No real-library migration or restore experiments are permitted.

`diagram-model.js` is the shared browser/server graph contract: 500 stable-ID nodes (`entry`/`text`), 2000 edges, coordinates ±100000, 120-character entry/edge labels, content-sized text annotations and 6000-character linked notes. Cycles and multiple relationships are valid. Optional direction is none/forward/both; absent direction preserves legacy forward arrows and old nonblank-label validation. Explicit neutral connections may be unnamed. Only matching reverse forward arrows with the same wording, uncertainty, color and weight share a double-ended visual; both original records/notes remain editable. Parallel lines use canonical curved lanes and measured node bounds. Unknown graph/node/edge fields survive saves. Colors and three weights are optional validated fields, with absent legacy defaults preserved. Click targets stay 20px on screen; overlap clicks select the nearest curve. No layout/render operation silently rewrites graph meaning.

The connection inspector uses labelled SVG radio choices for path styles and directional attachment controls around Auto, with selection states and hover help. Start/End markers temporarily identify the affected cards while these controls are hovered or focused. These controls retain the same optional routing contract.

Optional edge `routing` stores style (`automatic`, `straight`, `elbow`, `curve`), sourceSide/targetSide (`auto`, `top`, `right`, `bottom`, `left`), a relative `bend` for elbows or two relative `controls` for cubic curves. Coordinates are finite and bounded ±100000. Missing routing keeps the exact legacy quadratic path; Automatic remains available as a compatibility/default style. Straight parallels use separate attachment offsets, elbows stay orthogonal, and untouched curves start with a modest bow. Bend/control offsets travel with their attached cards; manually shaped routes do not pick up new automatic lane offsets. Automatic routing follows endpoints but does not promise obstacle avoidance. Shared reverse visuals require compatible sides/styles, mirrored label positions and no manual controls; the original directed records remain intact.

Optional `labelPosition` is a validated 0–1 fraction along the path. Dragging a label projects onto the existing path; paired records retain mirrored positions. Selected paths expose curve handles (with tangent guides) or an elbow-bar handle. Handles have a nearest-first 20px screen-space grab radius at every zoom, with proximity highlighting/cursor feedback; cards and connection labels take priority. Offset grabs retain the original handle-to-pointer offset to prevent jumps. Reshaping uses stable viewport pointer capture and one undo snapshot per gesture; Escape restores the pre-drag graph/history. Reset route removes only manual bend/control values, keeping style, ports, wording, notes, arrows, color, weight and unknown route fields. Label reset is independent. Snap-to-grid and handle editing affect local draft data until explicit Save.

Nodes optionally store boolean `locked`; graph `snapToGrid` is optional boolean. Position locks exclude cards from drag/keyboard moves and grid arrangement, while their content and relationships remain editable. Alignment/distribution requires selected cards to be unlocked, uses measured bounds and is atomic/undoable; distribution equalizes the gaps between differently sized cards. The Layout tools menu shows selection counts and Shift-click guidance, explains grid steps, and pairs named actions with small arrangement diagrams. Hover/focus help describes unchanged axes and fixed outer cards; disabled commands explain selection/lock requirements. Center actions name their axis, distribution is labelled Space evenly, and completed actions expose an inline Undo. A 20px world grid scales/pans with the camera when enabled; group dragging preserves offsets and shows temporary alignment guides. Alignment/distribution can produce fractional coordinates for precision. The padded camera and Fit cover route geometry as well as cards.

These are additive JSON fields on the existing graph, with no startup rewrite, SQLite schema or ZIP version change. Existing unknown fields, legacy IDs/directions, notes and @ registries remain intact. Current saves, duplicate canvases and portable ZIP recovery preserve routing, label positions, snapping and locks. Older builds ignore these controls, so use this build or later when editing such diagrams. Invalid geometry/locks/settings reject the save atomically; the editor keeps its draft. Tests use isolated libraries and recovery worlds.

`diagram-editor.js` retains immediate tools, selection/Shift multi-selection, group movement, signed positions, atomic multi-source connections, click-line customization, undo/redo (100 actions), search/neighborhood filtering, direct/connected-chain views, lock-aware grid arrangement, selection alignment/distribution, optional world-grid snapping, Fit, pan/zoom and optional connection list/inspector. Card names use one-line shared category badges at 15px base (bounded compensation when zoomed out), with a fixed-height name band and CSS ellipsis on the name only. Icons stay visible, accessible names remain complete and hover previews show full live names; connection labels use 11px base and a 10px screen floor. Text nodes are canvas-local annotations: plain text (new default), rectangle (legacy default), square, circle or diamond. Optional `shape`, `fontSize` (10–72), `align` (left/center/right), `fill` (theme palette/transparent), boolean `border`, and bounded `width`/`height` (80–1200) survive explicit saves/copies/backups. Text remains upright, grows to fit and is never clipped; measured Fit covers resized annotations. Visible `label` uses universal `textReferences.label` with a 2000-visible-character budget; optional `summary`/`description` use the shared budgets and owner-local registries. The inspector says Edit text, supports double-click focus, font size independent of lower-right resizing, lock/connection tools and descriptive hover previews (summary first, description fallback) with the same nested-badge lock/travel behaviour. Plain text gets a subtle boundary only on hover/selection; shaped selections follow the actual shape. Border/fill controls disable for plain text. One resize gesture is one undo step; pointer cancellation/Escape restore its starting draft. Explicit node descriptions are validated on each node owner. Entry artwork disables native image dragging. Field changes collect into the local draft with shared @ binding and reentrancy protection; there is no Apply step for diagram inspector edits. Invalid inspector drafts block switching/saving. Metadata Apply details is separate from diagram collection.

Fullscreen concentrates on diagram/tools by hiding the introduction, derived entry list and other reading content. It uses documentElement so dialogs and @ menus remain available, with an expanded in-app fallback. Explicit Escape/exit leaves fullscreen; native image-picker exits during entry or canvas-artwork editing retain the expanded workspace/draft/camera. Browser fullscreen re-entry stays an explicit action. Entry/era reading overlays preserve canvas drafts. Navigation/world/import exits use the shared discard guard, restoring camera/selection/filters without restoring browser fullscreen.

`EntryPreviews.mount` owns five-level interactive preview stacks: 180ms opening delay, 175ms closing grace (one extra 175ms only during active travel toward a panel), 600ms in-panel lock progress, duplicate-entry highlighting, descendant close, deepest-first Escape and collision-aware edge positioning. Panels are 350px wide with 14px text and intact reference badges.
